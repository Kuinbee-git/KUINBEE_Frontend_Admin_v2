**Claru deliveries: complete admin operating guide**

Use this guide to prepare, upload, submit, and follow up on Claru footage. The process is: prepare the recordings, organise them into a delivery batch, upload them, submit each clip, then track Claru's decision.

| Term in the panel       | Meaning                                                                              |
| ----------------------- | ------------------------------------------------------------------------------------ |
| Delivery batch          | A group of related recordings under one Claru project.                               |
| Clip                    | One recording, with its primary video and any related files.                         |
| Upload queue            | The list of clips this browser is preparing or uploading.                            |
| Clip external reference | Your team's unique label for one recording. Use it to identify and resume that clip. |
| Seal submission         | Finalise an uploaded clip and send it to Claru for validation and review.            |
| Approved                | Claru has accepted the clip. Uploading or sealing alone does not mean approval.      |

An admin needs permission to view deliveries, manage uploads, and seal submissions. If a required button is missing, ask the superadmin to check your permissions or assign that step to an authorised admin.

**1. Prepare the recordings and capture information**

Have the original MP4 videos, any required related files, and the recording information ready. Keep the original files available until the deliveries are resolved; an interrupted upload may require you to select them again.

For each recording, know its category, country, collector ID, site ID, camera/device, mount, actual recording start time, and duration. Use your team's assigned collector and site identifiers. Obtain missing information from the capture team before submitting.

Confirm that the footage meets the project's requirements and that worker consent, site/employer permission, and required consent or notice procedures are complete. Footage must be unedited except for permitted splitting or rewrapping.

**2. Sign in and open Claru Deliveries**

Open [the admin login page](https://admin.kuinbee.com/login), sign in with your assigned account, and select **Claru Deliveries** from the sidebar. Keep this browser tab open throughout uploading.

**3. Create a delivery batch or open an existing one**

Use **New delivery batch** for a new group of recordings. Open an existing batch when continuing that delivery or adding more recordings to it. A batch belongs to one Claru project.

| Batch field     | What to enter                                                           |
| --------------- | ----------------------------------------------------------------------- |
| Batch name      | A clear, required name, such as Factory A - Day 3 - Card 01.            |
| Claru project   | The required project assigned to this delivery.                         |
| Batch reference | Your team's delivery reference, if available, such as CLR-DAY03-CARD01. |
| Country code    | The two-letter capture-country code, such as IN.                        |
| Collector ID    | The identifier for the person who recorded the footage.                 |
| Site ID         | The identifier for the recording location.                              |
| Capture device  | The camera/device used for recording.                                   |
| Mount           | How the camera was mounted, such as head mounted.                       |

Only the batch name and project are required to create the batch. The other fields prefill clip information. Required clip information must still be complete before uploading; defaults remain editable for individual clips.

**4. Read Current project requirements**

On the batch page, check the displayed clip-length range, aspect ratio, required file roles, and any motion-sensor requirements. Required file roles have an asterisk. Follow the current rules shown for that project.

If the project connection is unavailable, use **Retry connection** or **Refresh projects**, depending on the page. If it remains unavailable or the team/project is blocked, report the displayed message to the superadmin before continuing.

**5. Select videos using Bulk upload**

Click **Bulk upload**, then select the MP4 videos. You can select several together and select more again to extend the selection. Each video becomes a separate clip; related files belong to that clip.

Check filenames and the selected count. Remove accidental duplicates. If a duplicate-selection warning appears, confirm the item only when it really is a separate recording.

Selecting files does not start an upload. Closing the form discards that unfinished selection.

**6. Enter shared details, then review each clip**

Shared capture details initially come from the batch. Change them if needed, then click **Apply shared details to all clips**.

Apply a shared category only when it is correct for every clip. Apply a shared recording time or duration only when those values really are the same. Recording time means the actual start time, not the file's modification date. Duration is read from the video where possible and remains editable; leave the shared duration blank to retain each clip's measured value.

Review every clip's reference, category, recording time, duration, and capture details. Change individual exceptions after applying shared details. Large selections have pages of 20 clips: review all pages. Shared changes apply across every page.

The reference prefix helps generate a label for each clip. For example, use CLR-DAY03-CARD01 for one group and CLR-DAY03-CARD02 for another. References must be unique across the team's batches. If you change the prefix after selecting files, click **Regenerate references** and review the results.

Numbering restarts with each new Bulk upload form. Selecting additional videos in the same open form continues the numbering. For new footage, use a distinct group prefix or edit references individually. To retry an existing recording, open its existing clip instead of adding that footage again.

**7. Attach related files and confirm consent**

Open **Capture details and related files** on a clip to correct capture details or attach related files. Attach files to the matching recording, following the required/optional labels. If motion-sensor details are requested, use the capture team's actual axis and timing information.

After selecting the final files, confirm all four statements for every selected clip:

- Worker consent has been obtained.
- Site or employer permission has been obtained.
- The required consent or notice process was followed.
- The footage is unedited except for permitted splitting or rewrapping.

If a statement is not true for one clip, remove that clip and resolve the issue before uploading it. Adding videos or attaching/clearing related files resets the consent checks; confirm them again after those changes.

Click **Add N clips to queue**, where N is the selected count. Correct any indicated incomplete or conflicting details. Adding clips to the queue does not submit them to Claru.

**8. Start and monitor the upload queue**

Click **Start queue**. Clips upload one at a time, each with its own progress. If a clip fails, the remaining clips can continue.

You can navigate within the admin panel while bulk uploads run. The header's **Upload queue** button opens the queue across batches. Keep the browser tab open and the computer awake while uploads are active.

| Queue status      | What to do                                                                 |
| ----------------- | -------------------------------------------------------------------------- |
| Waiting           | The clip is waiting for its turn. Start/resume the queue if stopped.       |
| Preparing         | Wait while the clip is prepared for upload.                                |
| Uploading         | Wait and monitor progress.                                                 |
| Saving progress   | Wait for completed work to be saved before refreshing or closing.          |
| Paused            | Resume the clip or queue when ready.                                       |
| Needs attention   | Read the error, fix its cause, and use Retry.                              |
| Reselect files    | Select the original unfinished files before resuming.                      |
| Ready to seal     | Upload is complete. Open the clip and submit it.                           |
| Already submitted | The clip has been sealed. Check its delivery status for the review result. |

**Start queue**, **Pause queue**, and **Resume queue** apply across all batches. **Retry failed**, **Clear uploaded**, and **Reselect queue files** apply to clips shown in the panel: the current batch on a batch page, or all batches in the header queue. Retry failed retries failed items without restarting successful ones.

An individual Pause targets one clip. An individual Resume or Retry targets that clip and activates the queue, so other Waiting clips can also continue. Other individually Paused clips remain paused. Pause individual entries first if you need them to remain stopped.

Removing an entry, including with **Clear uploaded**, only clears it from this browser's queue. It does not delete a submission already created in the batch. Pause an active entry and wait for Saving progress to finish before removing it.

**9. Review and submit each uploaded clip**

For each **Ready to seal** item, choose **Open clip**. Check its files and declaration, then select **Seal submission** and confirm with **Seal and submit**.

Do this separately for every clip. The queue does not seal automatically. If sealing controls are missing, ask an admin with sealing permission to complete this step.

An unfinished queue entry must finish or be paused and removed before you use that clip's separate correction or sealing controls. If a seal request times out, use **Refresh status** before retrying to check whether submission already succeeded.

**10. Track Claru's decision**

Return to the batch to find clips by reference or filename and filter by delivery state. Open a clip to inspect its status and messages. Processing and review views refresh automatically; **Refresh status** also checks the current result when available.

| Delivery status | Meaning and action                                                                              |
| --------------- | ----------------------------------------------------------------------------------------------- |
| Draft           | Not submitted. Finish any upload and seal it.                                                   |
| Processing      | Claru is processing/checking the clip. Wait for the next result.                                |
| In review       | Awaiting or undergoing review.                                                                  |
| Approved        | Claru accepted the clip. No further upload action is required.                                  |
| Refused         | Submission failed a gate. Read every failed check and remedy; correct under the same reference. |
| Expired         | The unfinished delivery expired. Restart under the same reference.                              |
| Rejected        | Claru rejected the submitted clip. Corrected footage needs a new reference.                     |

Uploading, sealing, and approval are separate stages. Do not report a clip as approved because its upload reached 100% or its queue status says Already submitted.

**11. Recover interrupted uploads**

- **A clip fails:** read the error, restore the connection or resolve the named issue, then choose Retry or Retry failed. Keep the same clip reference.
- **You need to pause:** choose Pause queue and wait for Saving progress to finish. Resume queue when ready.
- **You refresh the same browser tab:** the queue returns paused. Choose Reselect queue files, select the original unfinished files together, then Resume queue. Filenames and byte sizes must match. If several files share those details, use each clip's Reselect files button. Completed files and saved upload checkpoints are reused.
- **You close the tab, log out, or change accounts:** sign in, open the batch, and locate clips already created. For an unfinished clip, choose Resume upload, select the original unfinished files, choose Prepare upload, then Start upload. Keep that individual clip page open until its transfer finishes. Fully uploaded clips can proceed to sealing. Clips that never started may not exist in the batch; check their references before adding them again.

The browser queue is not a durable delivery record. The batch's created clips remain available after the browser queue is lost.

**12. Correct refusals, restart expired clips, or replace rejected footage**

For a **refused** clip, read the reason, every failed check, and the suggested remedy. Choose **Correct submission**. For a declaration-only correction, use **Declaration only**, correct the information, and choose **Save declaration**. To replace files, choose **Replace delivery files**, select the corrected files for every retained role, confirm consent, choose **Prepare corrected upload**, then **Start upload**. Give the corrected version a distinct filename, such as a filename ending in \_corrected.mp4, if its filename and size would otherwise match the old version: identical file declarations can reuse the old stored files. Seal again when the correction is complete. Keep the same clip reference.

For an **expired** clip, choose **Restart delivery**, reselect files for every retained role, including optional files previously declared, and review the declaration and consent. Remove any optional role that is no longer needed. Choose **Prepare corrected upload**, then **Start upload**. Seal after uploading. Keep the same reference.

For a **rejected** clip, read the rejection reason and address the underlying issue. Add the corrected footage as a new clip with a new reference, then upload, review, and seal it. Leave the old clip as the rejection record.

**13. Continue later deliveries and finish the batch**

To add more recordings for the same project and delivery, reopen the batch and use Bulk upload again. Use a distinct prefix or unique references for new footage. Open existing clips to resume unfinished work. Create another batch for a different delivery group or project.

Before ending a shift, check all pages of the batch and account for every expected recording. Finish or hand over unfinished uploads, seal uploaded drafts, and record outstanding refusals/rejections with their reasons. Hand over the batch name, clip references, current status, and next action. Another authorised admin can continue from the existing clips.

A delivery is accepted when its required clips are Approved. Track processing/review items and unresolved exceptions until they are resolved.

If a connection, permission, project, or validation problem cannot be resolved from the displayed instructions, give the superadmin the batch name, clip reference, exact error message, and the step where it occurred.
